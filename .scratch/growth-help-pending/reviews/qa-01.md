## Reading it as Discord shows it

I checked `help` and 13 printed states line by line. Backticks and `**` are balanced on every line. No
`<`, `>` or `||` sits outside backticks, and there is no stray `*`, `_` or `~`.

- **Headings** render bold, and the blank line between sections stays.
- **`- ` lines** render as a list.
- **Usage in backticks** keeps `<…>`, `[…]` and the single `|` literal. No `||` can read as a spoiler.
- **`#control` and `#mission-control`** show as plain text, not channel links, since Discord needs
  `<#id>`. They read fine.
- **Line lengths:**
  - `help`'s longest line is 151 characters, and most are under 80. At about 45 characters a line on a
    phone, it fills about 32 lines, which is fine for a list you look up.
  - `pending`'s approved line is 132 characters, and the claimed line is about 210.
  - A preview line runs from 327 to about 410, because it carries the link and the whole `apps built`
    command with a 40-character SHA. It is long but exact. It is capped at three, and sits below every
    other next step.
- **The bare preview link** may unfurl as an embed, unless Dispatch suppresses that. I couldn't check
  this from here.

## Exploratory charter

The charter: odd inputs, retries, two senders at once, a narrow width, damaged files, and doing what the
answer says. Defects 02 and 03 came from this. Everything else I found is below. None of it fails a
criterion, so none has a ticket.

1. **Request lines don't say what to send.** The ticket's opening says `pending` "says exactly what to
   send next", but its bullet asks only for id, title and decide-by, and the code follows the bullet. A
   line such as `A-0005 · … · decide by Sat 21 Nov, 23:05 SGT` leaves him to know `approve`. Adding
   `` `/growth approve A-0005` `` would fix it, but the longer line would need checking against a cut.
2. **A capitalised command is refused.** `Pending` and `PENDING` exit 2. A phone keyboard capitalises the
   first word of a plain message, so this is likely in `#control`. Every command has always behaved this
   way, and the refusal lists the right words.
3. **A held lock is worded as damage.** While a writer is simply running, the answer says `growth.db has
   an unfinished write. Send /growth status to clear it.` There's nothing to clear, and it passes on its
   own. The wording is shared with the read model's, and a test asserts it.
4. **Reasons name internals.** `(ValueError)`, `(no such table: …)`, `(SQLITE_CORRUPT)`. They are truthful.
   The backlog line doesn't say what to do next, and "check the file by hand" would help.
5. **Pausing changes nothing here.** After `pause all`, `pending` still heads its list "Growth is on it".
   The ticket doesn't ask for this.
6. **Markdown in a name renders.** An idea named `**bold** @everyone <@123> [x](https://evil.example)
   tan@example.com 91234567` comes out with the mentions defused and the address and number masked, but
   the bold and the masked link stay. The code review's nit about scraped titles stands, and it matches
   `/growth approvals`.
7. **The merge reply is unchanged.** It ends in `jura-growth apps released`, while `pending` says
   `/growth apps released`. Both work.

Also tried, with no fault found: the same `--ref` twice (two events, as the contract allows for a command that
isn't a decision), a read-only data folder (the answer still goes back), and whether masking can eat a
SHA in the ask-again line (five SHA shapes through `privacy.for_discord`; only a token of exactly eight digits is masked, and a stored SHA is 40 or 64 characters).

Not retested: the code review's note that `on_main` can take 30 seconds per claimed app if git hangs.
